# Nokia N97（S60v5）整机模拟实施计划

目标是在 v86 的新建虚拟机向导中提供 **Symbian → S60v5 · Nokia N97 → 选择 N97 固件**。用户用自己的固件启动原版 S60 主屏，能滑开键盘写便签，用实体菜单键切换应用，并安装、运行和卸载自己编写的 Symbian 软件。关机、关闭浏览器、重新打开后，手机应保留应用和数据。

首个验收型号为初代 **Nokia N97 RM-505**，对应 S60 5th Edition、Symbian OS 9.4。首套固件为 **22.0.110，产品代码 0576555，变体 001（MENA_MEA B black）**。阶段划分沿用 iPhone 4 从固件、机器、内核、主屏到浏览器冷启动的做法。自定义软件安装从首版起就是交付条件。[iPhone 4 整机计划](iphone4-plan.md) · [iOS 应用安装计划](ios-ipa-install-plan.md)

## 用户从哪里开始

1. **选择系统。** 在新建虚拟机的 **Source** 页，和 iOS、Android 同级显示 **Symbian**。选中后，在该选项下方就地显示机型选择器，首版只有 **S60v5 · Nokia N97**。选择 N97 后才展开固件选择区。将来在同一选择器增加 **S60v3 · 机型** 和 **Symbian^3 · 机型**，各自关联板型和固件目录。
2. **选择固件。** 支持选择本地固件文件夹，或一次多选一份 VPL 清单与它引用的配套文件。选中一份 VPL 时提示还需选择哪些文件。目录中有多个产品代码时，列出型号、版本、变体及可识别的语言，由用户选一套。VPL 及变体选择已有 Symbian 模拟器的使用先例。[EKA2L1 固件导入说明](https://eka2l1.github.io/quickstart/basic/installdevice/)
3. **预检和创建。** 文件旁显示识别结果。缺少部件时给出清单里的文件名，型号、版本或摘要不符时指出具体冲突。通过检查后填写虚拟机名称，确认固件版本、产品代码、逻辑容量和预计浏览器占用。完成时显示读取、校验、写盘进度，并允许取消。切换来源或机型会撤销旧检查，避免旧结果使新选项可提交。
4. **再次使用。** 从虚拟机库打开已创建的 N97，可直接冷启动或恢复挂起状态。控制台提供实体键、滑盖和“安装 SIS/SISX…”入口。设置中可查看固件身份，并分别管理手机数据和大容量存储。

## 固件与存储

- **固定可重复的输入。** S0 记录 RM 型号、产品代码、软件版本、所选 VPL、各部件用途、字节数及 SHA-256。根据清单和镜像头识别 CORE、ROFS 各层、UDA 及该变体要求的其他镜像。实际容器、分块、目标偏移和覆盖次序都由样本验证，同一目录里的其他变体不能自动混入。首个可选固件条目以这份清单为准。
- **保留原始布局。** 导入工具产出可重现的引导描述、只读固件基底和每台 VM 独立的可写介质。ROM/XIP 区保留客体地址，ROFS 保留各层的查找与覆盖关系，UDA 按该版本的初始内容构建。用一个已知系统文件、一个变体特有资源和首次启动写入的文件分别核对各层。
- **区分手机内存和大容量存储。** 验收时由客体文件服务器枚举盘符。预期 `Z:` 为只读系统视图，`C:` 为可写手机数据，`E:` 为内置 32 GB 大容量存储，可移除 microSD 单独建模。32 GB 指用户存储的标称容量，按块稀疏分配。客体写入、刷新、重启后重读，以及主机实际占用随已写块增长，都要测试。[Nokia 对 N97 存储及滑盖的产品说明](https://www.nokia.com/system/files/files/form20-f-09-pdf.pdf)
- **导入和恢复。** Worker 分块读取和校验，在临时对象中建盘，检查配额，写完后再登记 VM。取消、刷新或写满时清理本次临时对象，并保留已有 VM。固件和应用包在本机处理。快照绑定板型、固件摘要、可写盘代次以及已插入的介质，恢复前检查匹配。清除手机数据、格式化大容量存储和恢复快照分别测试，界面标明每项会影响哪些盘。

## 机器与引导

为 RM-505 新增独立的 `machine_type`（拟名 `nokia-n97`），使用现有 `cpu_type: "arm32"` 执行核心，新增经验证的 ARM11/ARMv6 型号。N97 对外呈现单核和固定机身配置。先以 128 MiB RAM 建立测试预算，RAM 可用范围、保留区和具体 CPU 修订以目标板资料及固件核对。Nokia 的 RM-505 板图给出了 RAPIDO、存储、供电、键盘与显示的连线，可定位控制器；MMIO 地址、中断号和复位值还要与该版启动代码逐项对应。[Nokia RM-505 板图](https://www.manualslib.com/manual/896600/Nokia-N97-Rm-505.html) · [N97 实机研究的设备配置，附录 C](https://www.diva-portal.org/smash/get/diva2%3A375044/FULLTEXT01.pdf)

| 子系统 | 实现与最早可观察结果 |
| --- | --- |
| ARM11 | 在现有 AArch32 解释器和 JIT 核对 ARM/Thumb 切换、异常入口和返回、CP15、短描述符页表、域权限、对齐及缓存/TLB 维护。只声明该核具备的指令与浮点特性。裸机程序覆盖缺页、一次定时中断及返回用户态。 |
| 引导 | 从选定固件确定 ARM 侧 bootstrap、ROM 头、加载地址、入口寄存器及内存布局。首选模拟开机加载器交接，从固件自带的 bootstrap 执行到 EKA2 内核和板级 variant。记录最后一个可重复的启动点、PC 和下一次硬件访问。 |
| 板级设备 | 先接入中断控制器、定时器、时钟、供电/复位、RTC、调试输出和启动介质。按原版驱动读写顺序实现寄存器、状态迁移、中断确认与 DMA 完成；用短迹线区分驱动在等时钟、I/O 或中断。 |
| 系统服务 | 让原版内核启动文件服务器、窗口服务器、应用架构服务和 S60 主屏。启动所需的 SIM、调制解调器或附件查询，先实现固件认可的无卡、离线和未连接状态，验收记录原版服务的实际响应。 |
| 显示 | 跟踪原版显示驱动设置的缓冲区、步幅、像素格式、刷新和方向，通过现有显示输出呈现竖屏 360 × 640、横屏 640 × 360。先用原版菜单、便签光标和窗口切换核对更新区域；应用调用的软件绘图或 GLES 按固件实际路径增加像素回归。 |
| 存储与电源 | 系统闪存、内置大容量存储和可移除卡按各自控制器接入。覆盖读写完成、介质插拔、冲刷、正常关机和意外断电恢复。锁屏唤醒与整机冷启动分别观察。 |

S0 的首要技术风险是从零售固件重建处理器可执行的 ROM 及板级交接状态。先用可定位的原版指令和第一次异常验证装载，再推进设备。若到不了内核，保留该版本的阻塞点和缺失证据。EKA2L1 可交叉核对固件解包结果，公开的 Symbian 内核可帮助理解 bootstrap、variant 与驱动接口；两者均需与 RM-505 固件对照。整机启动验收取自 v86 中运行的原版内核和系统服务。[Symbian 内核及硬件服务源码](https://github.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv) · [EKA2L1 项目](https://github.com/EKA2L1/EKA2L1)

## 触摸、实体键与滑盖

桌面鼠标或触屏的第一根手指驱动单点电阻屏。宿主按钮、键盘快捷键和自动化测试共用同一套板级输入事件；按下、松开、长按持续时间和滑盖位置交给原版驱动解释。N97 手册明确说明打开滑盖后应用转为横屏，并区分菜单、通话、锁定、音量、拍摄和键盘修饰键。[Nokia N97 用户手册，第 15–23 页](https://fcc.report/FCC-ID/QVVRM-505/1223966.pdf)

| 真机操作 | 浏览器入口 | 在原版系统中验收 |
| --- | --- | --- |
| 点按、双击、拖动、抬起 | 画面接受绝对坐标，按显示缩放与方向换算 | 点开菜单，滚动文件列表，两种方向分别点击四角和中心。 |
| 菜单、拨号、挂机 | 独立屏幕按钮和键盘映射，可按住 | 短按菜单进入应用列表，长按显示任务切换；离线打开拨号界面，再用挂机键返回。 |
| 电源、侧面锁定滑钮 | 分开的电源键和可拨动一次的锁定控件 | 客体处理长按电源、锁定、触摸被抑制、解锁和唤醒，连续操作两轮。 |
| 音量加减、拍摄键 | 两个音量键及支持半按、全按和松开的拍摄控件 | 查看音量等级变化并由客体输入记录核对拍摄键两段事件；相机成像另行验收。 |
| 滑盖、方向键与中央确认 | “打开/合上滑盖”，屏幕方向键，宿主方向键和 Enter | 打开后客体自行横屏，用方向键选中项目，确认键打开；合盖后按原版设置恢复方向。 |
| 全 QWERTY 键盘 | 宿主物理键与展开的可点击键盘共用扫描码，按固件变体选择布局 | 在原版便签输入字母、空格和标点，验证 Shift、Fn、Sym、退格重复及回车；保存后重开逐字比较。 |

把触点和按键当前状态纳入挂起与恢复。窗口失焦、指针取消捕获、合盖或切出控制台时，释放对应的宿主输入；滑盖位置独立保存。用长按中失焦、按住方向键时挂起和横屏拖动中合盖覆盖卡键、重复边沿和坐标错位。

## 安装自己的软件

首版支持与目标固件兼容的原生 **SIS/SISX**，包括用户用 S60 SDK 构建、按原版安装策略允许方式签名的应用。包 UID、版本、依赖、证书、capabilities、升级及卸载均以客体 Software Installer（SWI）和 Application Manager 的结果为准。[Symbian 安装中间件源码](https://github.com/SymbianSource/oss.FCL.sf.mw.appinstall)

1. 在 N97 控制台选 **安装 SIS/SISX…**，选本地文件。首版用虚拟 microSD 递送原包：在独立暂存卡镜像写入安装包，完成后交给客体挂载，界面提示从原版文件管理器打开包。若插槽中已有用户的卡，先提示从客体安全弹出。运行中每个已挂载卷只有一个写入方。
2. 用户在手机里查看包信息，选择目标盘并确认权限。由原版 SWI 写入文件和安装注册表，原版应用菜单发现新图标。浏览器将“已送入手机”和客体的安装结果分开显示；若只能观测到介质就绪，安装结果由手机显示。
3. 用一个可从源码重建、有独立 UID 的小应用做贯穿验收。v1 显示输入框并保存文本，v2 使用同一 UID 升级并读回该文本。分别验证安装、从菜单启动、接收触摸及按键、退出、冷启动后重开、升级、通过 Application Manager 卸载。另测取消、缺依赖、证书被拒和空间不足，失败后原有版本与用户数据应可继续使用。
4. 对需要 Java ME 的旧软件另设兼容性验收：经目标固件的 Java 安装器安装自编 JAR/JAD、运行 MIDlet 并重开存档。原生 SIS 和 Java 的支持状态分别记录。

## 阶段与完成标准

| 阶段 | 通过条件 |
| --- | --- |
| S0　固件基线 | 本地工具能重复识别同一套 RM-505 固件、列出清单和摘要，提取 ROM 头、入口、ROFS 与变体资源；能指出缺件和混包。形成第一版地址图、引导交接表和待测外设清单。 |
| S1　ARM11 与板级复位 | 裸机通过 ARM/Thumb、MMU、异常、IRQ 和定时器回归；同一配置下，原版 bootstrap 可重复执行到板级初始化。 |
| S2　内核与存储 | 原版 EKA2 启动文件服务器，客体从只读系统盘读取变体资源，在手机内存和大容量盘分别写入、刷新，断电冷启动后读回。 |
| S3　S60 主屏 | 原版窗口服务器和主屏从持久介质冷启动，完成离线首次设置；打开设置、计算器、便签，保存一条便签并重启验证。保留主屏与应用的客体画面和启动日志。 |
| S4　整机输入 | 逐项通过上表的触摸、菜单、通话键、锁定、音量、拍摄、滑盖、方向键和 QWERTY 验收；用设备边沿和原版界面反馈核对。 |
| S5　自定义应用 | 在同一台 VM 完成 SIS/SISX 安装、运行、存档、冷启动、升级和卸载，记录包 UID、版本、安装盘、客体结果及失败用例。 |
| S6　浏览器交付 | 从空库走完 **Symbian → S60v5 · Nokia N97 → 本地固件**。用 S3–S5 的便签和自编应用完成一次跨会话验收：在 CPU Worker 下挂起、恢复，再正常关机并关闭页面。从库冷启动，读回便签，打开升级后的应用并读回存档，最后卸载。 |

公开 CI 使用自制 VPL/镜像片段、裸机探针、输入序列和可分发的测试包，覆盖解析、机器状态、介质递送和向导。复用现有 `make a32-system-tests`、`make app-tests`、`make ios-tests` 检查公共路径。原版冷启动、主屏交互和 SWI 安装结果则在本地用用户固件验证，各阶段记录固件摘要、代码版本、日志、关键截图与实际结果。

首版整机里程碑是 S6。后续继续按外设记录支持程度：音频以客体实际播放和音量变化验收，相机以取景和保存照片验收，联网以原版浏览器请求本地测试页验收。基带/SIM、蓝牙、GPS 和 USB 各需独立的设备模型及测试。扩展到 S60v3 或 Symbian^3 时复用固件选择、安装入口和持久化，每个新机型重新完成板级启动、输入和应用兼容性验收。

## 实施与复核记录

### S0.1　固件清单与完整性（2026-11-18 通过）

在仓库根目录运行 `node tools/symbian/vpl.mjs list <固件目录>` 枚举变体，运行 `node tools/symbian/vpl.mjs check <固件目录> --product-code 0576555` 逐件检查。实测清单 `RM505_0576555_22.0.110_001.vpl` 的 SHA-256 为 `c779d64d3a5d4e5cc1e3a9611e28c3115857a14dce430118a9d8187bf6972c38`。7 个必需文件齐全，其中 6 个声明了 CRC-32 且逐一匹配，9 个可选文件缺失。清单没有给签名文件声明 CRC，工具记录其实测字节数和 SHA-256。这个结果证明包内文件与清单一致到上述程度。

CORE 为 111,508,110 字节，SHA-256 为 `d5b3cd2467edb812ab3a582b67168a962b47e40d222f90c52e89428bdbcf8a20`。同套固件还包括 ROFS2 V16、ROFS3 C01、UDA 4 和 ENO。复核时用 `node --test tests/symbian/vpl.mjs` 验证了缺件、同大小错件、重复部件、空 UDA、越界路径及只有元数据的清单均无法通过 RM-505 预检。

### S0.2　提取系统镜像（2026-11-18 通过）

运行 `node tools/symbian/vpl.mjs extract <固件目录> <新建输出目录> --product-code 0576555` 可生成 `firmware.json` 和七个输出文件。工具按 FPSX 记录的目标空间、证书分组及闪存地址重建镜像，对每块检查头与载荷校验。应用处理器的 `SOS+CORE`、三个 ROFS 和 UDA 分别提取。收包记录中的其他处理器镜像仍可在报告中辨认。

在独立解码中，1,954 个 BytePair 页和 34 个未压缩页还原出同一份 15,646,720 字节 XIP。逐字节对比通过，SHA-256 为 `9c0863e379d243f953d3cfcd87d11c98231f2d0469e69244d9ee059472c99194`。ROM 头的链接基址为 `0x80000000`，起始指令跳至 ROM 偏移 `0x1880`。在 ROM 目录中读到了 `ekern.exe`、`efile.exe` 和 `EStart.exe`。三层 ROFS 的字节数依次为 90,117,152、19,889,920、440，第二层的语言文件给出了 37、01（默认）、50，第三层有客户版本标识。UDA 的 FAT16 卷逻辑容量为 76,640,256 字节，固件提供的 9,216,000 字节恰好覆盖至最后一个已分配簇。[Symbian ROM 结构](https://github.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/blob/master/kernel/eka/include/e32rom.h) · [ROFS 结构](https://github.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/blob/master/userlibandfileserver/fileserver/inc/rofs.h)

### S1.1　执行原版复位入口（2026-11-18 通过）

`nokia-n97` 已有独立 ARM32 初始化入口。裸机测试覆盖 ARM/Thumb 切换、SVC 与 IRQ 返回、ARMv6 扩展短描述符和数据异常。首轮复核在两个实验装载地址执行了相同的原版指令：ROM 先向 SRAM `0x30000010` 保存 R0–R3，再向 `0x20040484` 写入 1。独立 ARM1136 模拟器复现了原版代码的两次初始寄存器写入，以及读取 R2 中 RAM 标签之后的前三次板级访问。虚拟机管理器的 81 种既有启动配置对照通过。[N97 引导验收与复现命令](../symbian-n97.md)

### S1.2　原厂加载地址、交接记录与内核入口（2026-11-18 通过）

原厂闪存目录与 RAP3NAND 加载器给出 XIP 物理地址 `0x08900000`、128 MiB 主内存和 16 KiB SRAM。常规 N97 入口已从该地址执行固件。复核时，原版读取了 R2 指向的交接记录，处理内存、时钟与冷启动原因，第 1,868 步在向 `0x20030300` 写入 `0xA` 时触发数据异常。独立测试覆盖 32,768 Hz 计时器的锁存和回绕，并在 Chrome 的 CPU Worker 中验证了新物理布局。

这一阶段的诊断曾为五处硬件地址提供限定响应。同一份 XIP 在第 29,804 步开启 MMU，第 1,336,740 步到达 ROM 目录所列 `ekern.exe` 入口 `0x8004F110`，执行第一条内核指令后 PC 为 `0x8004F114`。S1.3 后这些里程碑已可直接从默认机型复现。[逐地址记录与当前复现命令](../symbian-n97.md)

### 浏览器固件选择与建库（2026-11-18 通过）

新建向导提供 **Symbian → S60v5 · Nokia N97**，可选择整套目录或分次选择 VPL 与配套文件。Chrome 实测用原厂目录识别了 `22.0.110 / 0576555 / 001` 及阿拉伯语、英语（默认）、波斯语。Worker 校验并持久保存 XIP、三层 ROFS 和 UDA。关闭并重开虚拟机库后，CPU Worker 从 OPFS 读取 XIP，核对摘要并执行原版指令。

公开浏览器回归覆盖单份 VPL 提示缺件、目录补件只作用于当前变体、切换来源和取消后重新导入、回收上次中断留下的文件，以及两台 N97 各用独立 UDA。存储镜像已经落盘；原版文件服务器枚举、读写这些介质仍属 S2。[浏览器验收与复现命令](../symbian-n97.md)

### S1.3　默认机型进入原版内核并完成时钟初始化（2026-11-18 通过）

默认机型按 RAPIDO3G 1.13 建模，原版在第 29,801 步开启 MMU，第 1,336,737 步进入 `ekern.exe`，随后调用 RAPIDO variant，按原版流程启用 L2 并等到 PLL3 锁定。独立实测停在第 1,360,196 步：`0x800974C4` 向 VA `0xC6031C10`（PA `0x20031C10`）写 `0xAAAAAAAA`，触发外部数据异常。

在对照实验中，仅恢复模拟 CPU 原先的缓存类型寄存器值，原版便通过 XTI 通道 `0xE0` 发出 `CacheFault 116`。改为 ARM1136 定义的缓存类型后，同一份固件通过该处。16 项公开测试以及原厂 XIP 冷重置、快照回读通过。机型布局从 2 换为 3，较早实验版本的挂起状态需要冷启动重建。[机型与验收记录](../symbian-n97.md) · [Arm ARM1136 技术手册](https://developer.arm.com/documentation/ddi0211/k/)

### S2.1　原版内核处理定时中断并返回（2026-11-18 通过）

修正加载目录中 `MCUSW` 的起址后，原版内核完成 RAM 保留页分配和线程浮点上下文切换。板级定时器由固件装入 9600 计数并启用 IRQ 35。原版中断服务程序读取源编号、检查零计数、重载下一周期，随后内核执行延后调度，恢复原有 CPSR 和被中断的指令。

在每毫秒 8,000 步和 10,000 步的两次独立复核中，内核均通过 `0x8004F354` 的异常返回指令回到 `LR_irq - 4`。前者恢复到 `0x8008F640`，后者恢复到 `0x8008EC04`。随后原版变体在 `0x80096144` 报告 `RapidoVariant 0x200002C0`。现场五项加载记录计数为 1、1、1、1、0，缺少的第 18 号记录由原厂加载器提供片上 ROM 跳转表地址。18 项公开测试和原厂固件快照回读通过，文件服务器启动与磁盘读写仍待验收。[运行命令与中断总线记录](../symbian-n97.md)

### S2.2　零售基带映像与片上 ROM 的调用边界（2026-11-18 通过）

从 `0576555` 的 CORE 重建加载器实际交给处理器的映像。DSP0 和 ISASW 各自保留 RM-505 所用的 1,024 字节证书，后接解压数据。用独立提取结果逐字节比较，`0x08200000` 的 DSP0 为 1,820,720 字节，`0x08480000` 的 ISASW 为 3,893,852 字节。加上 CORE 前缀和 XIP 身份后，`rapido-boot.bin` 的 SHA-256 为 `de16da82ffe3a83fc376fefaa494470850648d5b0aec6d4507c931ada1075e74`。

按零售配置启动，原版 XIP 第 1,470 步从 Thumb 入口 `0xFFFF1208` 调用 RAPIDO 片上 ROM，传入描述符和 ISASW 地址。升级包中尚未找到与这块芯片匹配的 ROM，未提供时第 1,471 步发生取指异常。另用仅返回错误码 45 的自制 Thumb 测试文件确认了映射和调用返回，这项测试未运行原厂 ROM 服务。显式 `--ap-only` 诊断可在独立路径进入原厂 `dma.dll`，S60 主屏和安装器仍待零售路径验收。[复现方法](../symbian-n97.md)

Chrome 的公开夹具与原厂目录均通过导入、持久化和重开验收。复核还用上一提交生成了一份真实的第 4 版快照，当前第 5 版在同一仅 XIP 配置恢复到 `0x08900AC0`，加载基带的另一台机器拒绝了该快照。

### S2 存储验收的固件对照

从同一 XIP 的 ROM 目录提取 `Sys/Data/ESTARTCOMP.TXT`（1,465 字节，SHA-256 `2db34d7e03f78b4faaff112ccfb49439c0e80990c89ffada325ad6ba0ecfde4a`）。它指定 `Z:` 把本地驱动 9、10、11 的 ROFS 叠加到 ROM 文件系统，`C:` 采用驱动 6 的 FAT，`E:` 对应驱动 3 的内置 eMMC，`F:` 对应驱动 2 的可移除卡，`D:` 是驱动 0 的 RAM 盘。后续客体挂载和软件包递送均可用这个对应关系验收。ROM 目录同样包含 `mednand.pdd`、`MEDMMC.PDD` 和 `erofs.fsy`；原厂 CORE 外容器声明 `XSR 1.5`。在 RM-505 实机读取记录中，系统闪存返回三星 MuxOneNAND `00EC 0040`，版本 `0121`。[RM-505 实机识别记录](https://forum.gsmhosting.com/vbb/6948033-post1.html)

该版 CORE 的 `0xEE` 字段位于文件偏移 `0x110`。其中四个区段的闪存起址和长度分别为 `0x00080000 / 0x019A0000`、`0x01A20000 / 0x09180000`、`0x0ABA0000 / 0x04B80000`、`0x0F8C0000 / 0x00160000`。第二段从 ROFS1 的证书起算，镜像头位于 `0x01A21000`。第三段与 UDA 的 FAT16 卷同起于 `0x0ABA0000`。该分区长 79,167,488 字节，FAT16 的 BPB 声明卷长 76,640,256 字节，卷尾到分区尾相差 2,527,232 字节。OneNAND 的器件寄存器使用 16 位字地址，型号寄存器字地址 `0xF001` 对应字节偏移 `0x1E002`。[三星 OneNAND 寄存器定义](https://codebrowser.dev/linux/linux/include/linux/mtd/onenand_regs.h.html)
